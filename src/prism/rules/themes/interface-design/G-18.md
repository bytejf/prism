# G-18：接口定义在使用方，而且要小

**默认严重程度**：medium

## 规则
- 接口由**使用方**定义（它只需要自己用得到的那几个方法），不要由实现方定义一个大接口
- 接口方法越少越好：`io.Reader` 只有一条。使用方依赖的方法越多，实现方越难复用
- 不要为了「将来能换实现」提前造接口 —— 那是 YAGNI；**第二个实现出现时**再抽
- 实现方返回具体类型（见 G-19），使用方按需要收窄成接口

## 正例
```go
// 在需要读配置的那个包里定义它：
type configReader interface{ ReadConfig(path string) (*Config, error) }
```

## 反例
```go
// 在实现方定义一个大接口，所有使用方都被迫依赖全部方法（含它们不用的）
type Storage interface {
    Get(key string) ([]byte, error)
    Set(key string, value []byte) error
    Delete(key string) error
    List(prefix string) ([]string, error)
    Stats() Stats
    Close() error
}
```

## 边界情况
- 公开 API 里为了让调用方不依赖具体实现，定义接口是合理的（标准库也这么做），但要小
- 已经有第三方实现的接口（插件点、驱动）不适用「使用方定义」这条
