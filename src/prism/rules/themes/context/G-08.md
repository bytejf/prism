# G-08：`ctx` 是第一个参数，且从上层传进来

**默认严重程度**：medium

## 规则
- 需要 `context.Context` 的函数，`ctx` 放**第一个参数**、名字就叫 `ctx`
- 深层函数里凭空 `context.Background()` / `TODO()` 会把超时与取消整条链断掉：上层取消不了它
- `Context` 走参数，不要用全局变量或结构体字段传（见 G-09）
- 函数拿到 `ctx` 后要真的用它：至少把取消信号往下传，或检查 `ctx.Err()`

## 正例
```go
func (c *Client) Fetch(ctx context.Context, id string) (*Item, error) {
    return c.get(ctx, "/items/"+id)
}
```

## 反例
```go
func (c *Client) Fetch(id string) (*Item, error) {
    ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
    defer cancel()          // 超时是这里定的，调用方无法收紧或放宽
    return c.get(ctx, "/items/"+id)
}
```

## 边界情况
- `main` / 测试入口 / 后台任务的起点**应该**用 `context.Background()`，那是链条的根
- 请求级的值（trace id、用户身份）放 `ctx` 是正路；可选参数、配置项不该塞进来
