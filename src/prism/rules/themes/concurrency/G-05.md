# G-05：goroutine 必须有退出路径

**默认严重程度**：high

## 规则
每一个 `go` 出去的 goroutine 都要能回答：**它什么时候结束**。三种可接受的答法：

- 循环里有 `select { case <-ctx.Done(): return; case ... }`
- 有一个明确的停止信号（关闭的 channel、`Stop()`、`sync.WaitGroup` 等到它退出）
- 它的工作量有界（跑完就自己结束）

没有退出路径的长驻 goroutine 会泄漏，且**泄漏的 goroutine 会一直握着它引用的内存**。

## 正例
```go
go func() {
    ticker := time.NewTicker(interval)
    defer ticker.Stop()
    for {
        select {
        case <-ctx.Done():
            return
        case <-ticker.C:
            flush()
        }
    }
}()
```

## 反例
```go
// 调用方无法让它停下来；errCh 没人读时它还会永久阻塞
go func() {
    for {
        drain()
        time.Sleep(time.Second)
    }
}()
```

## 边界情况
- `go func() { ... }()` 里引用循环变量，Go 1.22 起每轮一个新变量，**不用再显式拷贝**
- 用 `context.WithCancel` 起 goroutine 的，要确认 `cancel()` 一定会被调用（`defer` 或跟着结构体生命周期）
