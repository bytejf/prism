# 代码审查规则索引

## 错误处理
错误要带上上下文、能被判定，并且不允许被静默丢掉。

| 代码特征 | 规则代号 |
|---|---|
| 错误消息没上下文 / 大写开头 / 用 `%v` 包装 | EH-G-01 |
| `err == ErrX`，或比较错误字符串（`err.Error() == "..."`） | EH-G-02 |
| `err` 被丢掉：空 `if` 体、只记日志后继续 | EH-G-03 |
| 遇到可预期的失败就 `panic` | EH-G-04 |

## 并发
goroutine 要有退出路径，共享状态的读写都要持锁。

| 代码特征 | 规则代号 |
|---|---|
| `go func()` 没有退出条件 → 泄漏 | CC-G-01 |
| 接收方关闭 channel、或两处都关 | CC-G-02 |
| 写入持锁、读取不持锁（或反之） | CC-G-03 |

## Context
ctx 从上层传入、走参数，不存进结构体。

| 代码特征 | 规则代号 |
|---|---|
| 需要 ctx 却不是第一个参数；或深层函数里凭空造 `context.Background()` | CX-G-01 |
| `ctx` 存进结构体字段 → 生命周期说不清 | CX-G-02 |

## 命名
名字要符合 Go 惯例，长度与作用域匹配。

| 代码特征 | 规则代号 |
|---|---|
| 缩略词大小写不一致（`userId` / `Url` / `httpId`） | NM-G-01 |
| 导出的取值方法带 `Get` 前缀（`GetName()`） | NM-G-02 |
| 三行作用域的变量取长名字，或大作用域用单字母 | NM-G-03 |

## 注释
注释解释为什么，且不能与代码实际行为脱节。

| 代码特征 | 规则代号 |
|---|---|
| 导出符号没有注释，或注释不以符号名开头 | CM-G-01 |
| 注释只复述代码在做什么，没写为什么这么写 | CM-G-02 |
| 新增 `TODO` / `FIXME` 没写清是什么情况、谁跟进 | CM-G-03 |

## 测试
测试要能定位失败、能独立跑，覆盖错误路径。

| 代码特征 | 规则代号 |
|---|---|
| 手写重复的测试函数没用表驱动；断言不带输入与 got/want；用例间有顺序依赖 | TS-G-01 / TS-G-02 |

## 接口设计
接口定义在使用方、尽量小，返回具体类型。

| 代码特征 | 规则代号 |
|---|---|
| 接口定义在实现方；或方法过多（>3 条）→ 使用方被迫依赖用不到的方法 | IF-G-01 |
| 只返回接口而不返回具体类型 | IF-G-02 |

## 性能
已知规模就预分配，别在热路径里反复分配。

| 代码特征 | 规则代号 |
|---|---|
| 已知长度的切片用 `append` 逐个长 | PF-G-01 |
| 循环里用 `+=` 拼字符串 / 反复做 `[]byte` ↔ `string` 转换 | PF-G-02 |

## 安全
敏感信息不外泄，随机数与外部输入都要按安全要求处理。

| 代码特征 | 规则代号 |
|---|---|
| 日志 / 错误消息 / 响应里带上 token、密码、主机信息 | SC-G-01 |
| 安全用途（令牌、盐、密钥、会话 ID）用了 `math/rand` | SC-G-02 |
| 外部输入直接进命令、文件路径、SQL | SC-G-03 |
