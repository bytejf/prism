# G-22：敏感信息不许进日志、错误消息与响应

**默认严重程度**：high

## 规则
以下东西不允许出现在日志、错误消息、返回给客户端的响应、监控标签里：

- 凭证：token、密码、私钥、cookie、`Authorization` header
- 个人数据：完整手机号、身份证、邮箱（要记就脱敏）
- 内部信息：内网主机名、IP、连接串、堆栈里带出的路径与配置

常见形态：`log.Printf("auth failed: %v", req)` 把整个请求打出来（含 header）、
把配置结构体整体 `%+v`、错误消息里拼上 `dsn`。

## 正例
```go
log.Printf("auth failed: user=%s reason=%s", userID, reason)   // 只要定位需要的那两项
```

## 反例
```go
log.Printf("auth failed: %+v", req)                    // req 里有 Authorization header
return fmt.Errorf("connect failed: %s", dsn)           // dsn 含密码
```

## 边界情况
- 调试级别日志也不例外（生产常开），要记就得脱敏
- 判断标准是「这条信息泄露出去有没有后果」，不是「它看起来像不像密码」
