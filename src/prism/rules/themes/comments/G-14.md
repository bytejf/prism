# G-14：注释解释「为什么」，并且不能与代码实际行为脱节

**默认严重程度**：low

## 规则
- 注释的价值在于代码本身表达不了的东西：**为什么这么写**、绕开了什么、有什么前提
- 复述代码在做什么的注释是噪音（`i++ // i 加一`），而且它会在代码改动后变成错的
- 这次改动如果改了行为，**同一次改动里**要把相关注释一起改掉：注释、错误消息、日志文案都算
- 注释里承诺的不变量（「一定非空」「总是先初始化」）必须真的成立 —— 不成立时，注释比没有更糟

## 正例
```go
// 这里必须用 Insert 而不是 Save：Save 会在主键冲突时回退成更新，
// 而调用方依赖「重复写入报错」这个语义（见 issues/482）。
```

## 反例
```go
// 返回 s 去掉首尾空白之后的结果
return s                        // 与注释说的不是一回事 —— 注释已经被改动作废
```

## 边界情况
- 大段算法说明放在函数开头是正路；与代码逐行对应的注释应该删掉，让代码自己说
- 注释里出现的符号名、参数名、文件名要跟着重命名一起改（改名漏改注释是常见形态）
