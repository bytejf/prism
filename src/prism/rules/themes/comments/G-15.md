# G-15：`TODO` / `FIXME` 要写清是什么情况

**默认严重程度**：low

## 规则
新增的 `TODO` / `FIXME` 至少要能回答两件事：**这里缺什么**、**什么条件下该回来处理**。
只写 `// TODO: 优化` 的，下一个人无法判断该不该动。

带上跟踪入口（issue 号、负责人）更好。**临时调试残留**（注释掉的代码、调试打印、
`XXX` 占位）不该留在提交里。

## 正例
```go
// TODO(#482): 这里现在是全量扫描，等索引建好后换成按 key 查。
```

## 反例
```go
// TODO: 优化
// FIXME
// x := compute()      // 注释掉的旧实现，没有任何说明
```

## 边界情况
- 早就在仓库里的 `TODO` 不是这次改动引入的，不必在本次审查里提
- 删掉一个 `TODO` 时，确认它对应的那件事真的做完了（而不是需求变了）
