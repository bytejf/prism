# G-07：共享状态的读也要持锁，锁要成对且同一把

**默认严重程度**：high

## 规则
- 写的时候持锁、读的时候不持锁，是数据竞争；`map` 上并发读写会直接崩进程
- 同一份数据的所有访问路径要用**同一把**锁（新增了一条访问路径，要确认它拿了同一把）
- 锁的作用范围要能一眼看出成对：`defer mu.Unlock()` 或紧邻的 `Lock` / `Unlock`
- 别在持锁期间做慢操作（网络、磁盘），也别在持锁期间回调外部代码（会引入锁顺序问题）

## 正例
```go
func (s *Store) Get(key string) (string, bool) {
    s.mu.RLock()
    defer s.mu.RUnlock()
    v, ok := s.data[key]
    return v, ok
}
```

## 反例
```go
func (s *Store) Set(key, value string) {
    s.data[key] = value      // 没持锁：与持锁的另一条路径并发就是竞争
}

func (s *Store) Snapshot() map[string]string {
    s.mu.Lock()
    copy := maps.Clone(s.data)
    return copy              // 忘了 Unlock：下一次调用直接死锁
}
```

## 边界情况
- 只读的**不可变**数据（初始化后不再改的）不需要锁；但「它会变吗」要用代码证明，不能靠印象
- `RWMutex` 的 `RLock` 不能在递归里重入，会死锁
