# G-17：测试要能独立跑，且不污染全局状态

**默认严重程度**：medium

## 规则
- 用例之间不能有顺序依赖：单独跑某一个用例必须也能过（`go test -run TestX`）
- 改了全局变量、环境变量、工作目录、共享文件的，用 `t.Cleanup` 还原
- 起了 goroutine / 后台任务的测试要等它结束，否则它会在**下一个用例**里继续跑，制造随机失败
- 时间、随机数、外部网络这些不确定源要么注入、要么固定，不要靠「一般都能过」

## 正例
```go
func TestWithEnv(t *testing.T) {
    t.Setenv("MODE", "test")      // 自动还原，且不允许并行 —— 正好
    if got := Mode(); got != "test" {
        t.Fatalf("Mode() = %q, want %q", got, "test")
    }
}
```

## 反例
```go
func TestA(t *testing.T) { os.Setenv("MODE", "test"); ... }   // 不还原，污染后续用例
func TestB(t *testing.T) { go worker(); ... }                 // 不等它退出
```

## 边界情况
- `t.Parallel()` 与 `t.Setenv` 互斥，同时用会直接失败 —— 两者取一个
- 集成测试依赖真实服务时，用「服务不可用就 skip」而不是让它红
