# G-06：channel 的关闭责任在发送方，且只关一次

**默认严重程度**：high

## 规则
- **只有发送方关闭** channel。接收方关它，会让发送方在下一个 `send` 上 panic
- 用 `range ch` 等「不再有值」时，依赖的是发送方关闭；没有关闭路径就会永久阻塞
- 不要在两处都关：`close` 两次直接 panic
- 用关闭 channel 表达「结束了」时，别再用它传值 —— 两种用途混在一起没法判读

## 正例
```go
go func() {
    defer close(out)        // 唯一的发送方负责关闭
    for _, item := range items {
        out <- item
    }
}()
```

## 反例
```go
go func() {
    for item := range in {  // 等 in 被关闭，但没人负责关它 → 永久阻塞
        out <- item
    }
}()
close(in)                   // 接收方关掉了别人的 channel
```

## 边界情况
- 多个发送方时用 `sync.WaitGroup` + 一个转发 goroutine 收口，别让每个发送方都试着关
- 无缓冲 channel 在没有并发接收方时会把发送方**同步阻塞**住，这常常就是「卡死」的现场
