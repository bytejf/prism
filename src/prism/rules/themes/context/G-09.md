# G-09：不要把 `ctx` 存进结构体

**默认严重程度**：medium

## 规则
`context.Context` 代表的是**一次调用**的生命周期，把它存进结构体字段会让生命周期说不清：

- 结构体的寿命通常比一次请求长，存进去的 `ctx` 会在请求结束后还在被用
- 创建结构体的人与用 `ctx` 的人不是同一个，取消信号的来路就丢了

## 正例
```go
type Fetcher struct{ client *http.Client }

func (f *Fetcher) Get(ctx context.Context, url string) (*Item, error) {
    return f.do(ctx, url)     // ctx 走参数
}
```

## 反例
```go
type Fetcher struct {
    client *http.Client
    ctx    context.Context   // 存进来之后，这个 Fetcher 就成了「绑在某次请求上」的
}
```

## 边界情况
- 框架层把 `ctx` 包一层放进 `*http.Request` 之类是标准做法，那是标准库的接口形态，不算违反
- 测试辅助类型里存一个「根 ctx」也算，但要在注释里写明它只用于测试
