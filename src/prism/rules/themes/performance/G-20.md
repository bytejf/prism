# G-20：已知规模就预分配

**默认严重程度**：low

## 规则
- 能算出元素个数时用 `make([]T, 0, n)`：`append` 的扩容是复制整个底层数组，长切片上代价明显
- 用 `map` 前知道大概条目数时给个容量提示（`make(map[K]V, n)`）
- 在 `for range` 里累积时，别每次迭代都新建切片/缓冲区

## 正例
```go
apps := make([]string, 0, len(specs))
for _, spec := range specs {
    apps = append(apps, spec.Name)
}
```

## 反例
```go
var apps []string
for _, spec := range specs {
    apps = append(apps, spec.Name)   // 反复扩容 + 复制
}
```

## 边界情况
- 循环里 `append` 的切片如果是**函数局部、量级很小**（几条），预分配带来的收益低于它增加的噪音 —— 判的时候看规模，不要当成形式要求
- 真正热的地方优先看**有没有重复分配**（每轮都 `make` 一个缓冲区），那比预分配更值钱
